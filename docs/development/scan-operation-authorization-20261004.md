## Selected operation policy

An internal whole scan or generic task authorizes its complete operation scope
at startup. Later user/session permission, root approval and authorization
configuration changes affect the next operation. The current operation retains
its startup grant until actual completion; a retry or later phase cannot perform
a hidden fresh permission query. This explicitly replaces the prior internal
per-phase fresh-approval policy. Cancellation and resource completion remain
independent live requirements.

Scan startup captures every enumerated root, approved route/domain and anchor
scope before walking, including later roots and cross-root work. Scan helpers
reuse that operation root/route snapshot, remove per-phase authority SQL and
redundant per-file complete-topology checks where exact file witnesses supply
the necessary identity. Destructive reconciliation retains complete rooted
membership, storage/topology, source-absence and mapping evidence.

Generic task admission verifies actor authority once and retains sealed work
identity. Internal Analysis and subtitle-provider executors create a private,
child/library-scoped opaque context grant and retain actual approved/registered
root handles. Context-aware generic route/open/lease helpers use it only when
valid and present. No serializable bearer authority, global registry or TTL
cache is added. Legal legacy unbound configured roots keep their read behavior
without gaining destructive deletion authority.

## Preserved external and data contracts

External API/admin/configuration requests, playback, downloads, sidecar delivery
and provider credential checks retain their existing fresh authorization.
External Analysis source/cache/cohort stamps and protocol are unchanged.
Internal source/cohort comparisons parameterize captured startup binding
revisions while recomputing current media, file/root mapping, identity, size,
timestamps, hierarchy, manual edits and cohort membership. An operation can
finish under its startup stamp; a later external reader can classify that old
stamp as stale after an approval change. No schema migration or global cache
version rewrite is selected.

Executor token and owner identity, Store ownership, active run/child/job
associations, cancellation/deadline, data and source integrity, mapping and
concurrent catalog/manual edits remain live fences. Final owned publication
locks, item/role/source checks, complete deletion evidence and accepted prefixes
remain. Quotas, root/domain admission, actual held-root/reader lifetime,
retirement mutexes, dedicated PostgreSQL owner session and unknown-resource
cleanup are preserved. A broader asynchronous quarantine/cleanup redesign is
not part of this simplification. The private one-slot observation channel is
removed only where PrimaryRootIO already enforces retained-worker bounds.

## Operation policy and classifier limit

This batch intentionally changes internal operation authorization: actor permissions are checked at operation startup, and the admitted snapshot/routes and task grant remain in force during that operation. Permission changes apply to the next operation. Cancellation, owner-loss fencing, catalog atomicity/concurrent edits, source identity, deletion safety and resource retirement remain independent guards. The unchanged v2 driver recognizes earlier AUTH SQL families. Its classified AUTH counters are a subset and may omit new startup SQL. They cannot establish the total number of operation authorization transactions or prove zero startup checks. Raw SQL/BEGIN/COMMIT counts and untraced timings retain their original measurement scope; startup-check behavior is established separately by frozen source and selected correctness evidence. Evidence qualification does not assert uniform performance improvement.

## Policy and classification

An internal operation authorizes its complete scope at startup and retains that grant until it finishes. Revocation affects the next operation. Cancellation, Store ownership, immutable task identity, source identity, data integrity, bounded resource retirement, and concurrent write protection remain live requirements. External API requests, administrator mutations, playback, downloads, and provider credential checks retain their existing authorization behavior.

The scan's repeated authority SQL does not ordinarily consult a user's ACL. It combines task ownership/cancellation with root configuration and stored root approval. The change separates these concerns: capture permission and approval once; preserve cancellation and source/catalog invariants.
